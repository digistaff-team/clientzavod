# Клиент Завод / Docker Claw

## Назначение проекта

`Клиент Завод` — это платформа с персональным AI-агентом, который работает в изолированном Docker-окружении каждого пользователя. Проект объединяет веб-панель, Telegram, Email, HTTP-вебхуки, файловое хранилище, персональную PostgreSQL-базу и модуль автоматической генерации контента.

Основная идея проекта:

- для каждого пользователя создаётся отдельная sandbox-сессия;
- внутри сессии агент может выполнять команды, работать с файлами и приложениями;
- управление доступно из браузера, через Telegram-бота, по email и через webhook API;
- контекст пользователя сохраняется между сессиями;
- результаты работы не теряются после перезапуска сервера.

---

## Ключевые функциональные возможности

- персональный Docker-контейнер для каждого `chat_id`;
- автоматическое создание рабочих директорий `/workspace/input`, `/workspace/output`, `/workspace/work`, `/workspace/log`, `/workspace/apps`, `/workspace/tmp`;
- интерактивная Bash-консоль в браузере;
- загрузка, просмотр, удаление и скачивание файлов;
- персональная PostgreSQL-база данных на пользователя;
- запуск и управление приложениями через `pm2`;
- AI-агент с системным контекстом, навыками и персонализацией;
- подключение AI-провайдера: ProTalk, OpenAI или OpenRouter;
- работа через Telegram-бота;
- обработка входящих писем по IMAP и отправка ответов по SMTP;
- поддержка cron-задач и фоновых сценариев;
- webhook API для запуска AI-агента извне;
- пользовательские хуки `/hook/:chatId` для собственных обработчиков внутри контейнера;
- модуль контент-пайплайна: генерация, модерация, публикация, метрики;
- хранение пользовательской конфигурации и логов;
- авто-восстановление сессий, бэкапы и снапшоты.

---

## Как устроена работа пользователя

1. Пользователь входит по Telegram ID или создаёт новую сессию.
2. Система поднимает персональный контейнер и готовит рабочее окружение.
3. Пользователь настраивает каналы, AI и персонализацию.
4. После этого можно:
   - давать команды AI-агенту;
   - работать с файлами и БД;
   - запускать приложения;
   - принимать задачи из Telegram, Email или webhook;
   - использовать контент-модуль для публикаций.

## Модули приложения и инструкции по работе

## 1. Авторизация и старт сессии

### Что делает модуль

- авторизует по Telegram ID;
- находит существующую сессию или создаёт новую;
- показывает статус инициализации контейнера;
- сохраняет `chat_id` в браузере для работы со всеми разделами панели.

### Как пользоваться

1. Откройте веб-панель.
2. Введите свой Telegram ID.
3. Если сессия уже существует, система выполнит вход.
4. Если сессии нет, она будет создана автоматически.
5. Дождитесь завершения инициализации контейнера.

### Что важно знать

- `chat_id` является главным идентификатором пользователя в системе;
- при первом запуске подготовка окружения занимает больше времени;
- после входа становятся доступны все остальные модули.

## 2. Модуль "Персонализация"

### Что делает модуль

Раздел отвечает за долговременный контекст AI-агента. Пользователь редактирует специальные файлы, которые затем автоматически добавляются в системный контекст агента.

### Файлы персонализации

- `IDENTITY.md` — кто такой агент, его роль, специализация, позиционирование;
- `SOUL.md` — характер, стиль общения, тональность;
- `USER.md` — информация о пользователе, бизнесе, задачах, ограничениях;
- `MEMORY.md` — важные инструкции, регламенты, токены, рабочие правила.

### Как пользоваться

1. Откройте раздел `Персонализация`.
2. Выберите нужный файл.
3. Заполните или обновите содержимое.
4. Нажмите `Сохранить`.
5. Повторите для остальных файлов, если нужен более точный контекст.

### Практическая рекомендация

- в `IDENTITY.md` описывайте роль агента;
- в `SOUL.md` фиксируйте стиль ответов;
- в `USER.md` храните сведения о компании, ЦА, продукте;
- в `MEMORY.md` добавляйте критичные рабочие правила и чувствительные данные.

## 3. Модуль "Каналы связи"

### Что делает модуль

Раздел объединяет подключение каналов, через которые пользователь может управлять агентом.

### 3.1. Telegram

#### Возможности

- подключение пользовательского Telegram-бота по токену;
- подтверждение владения ботом через код;
- привязка одного подтверждённого пользователя к управлению окружением;
- запуск и остановка Telegram-бота из панели.

#### Как пользоваться

1. Получите токен у `@BotFather`.
2. В разделе `Каналы` вставьте токен в блок `Телеграм Бот`.
3. Нажмите `Сохранить токен`.
4. Напишите подключённому боту любое сообщение.
5. Полученный код введите в поле подтверждения.
6. После успешной верификации управление через Telegram станет активным.

### 3.2. Email

#### Возможности

- чтение входящих писем через IMAP;
- обработка новых писем как команд для AI-агента;
- отправка ответов пользователю через SMTP;

#### Возможности

- отображение статуса периодических задач;
- просмотр логов опроса email;
- ручной запуск poll-задачи без ожидания планового цикла.

#### Как пользоваться

1. Откройте блок `Cron задачи`.
2. Нажмите `Обновить статус`, чтобы увидеть текущее состояние.
3. Используйте `Тест poll сейчас`, если нужно немедленно проверить email-обработку.

## 4. Модуль "ИИ"

### Что делает модуль

Раздел управляет AI-провайдером, моделью, параметрами контекста и отображением итогового system prompt.

### Поддерживаемые режимы

- `ProTalk AI`;
- `OpenAI`;
- `OpenRouter`.

### Возможности

- переключение провайдера;
- сохранение API-ключа или параметров ProTalk;
- выбор модели;
- контроль баланса и блокировок;
- настройка объёма контекста;
- просмотр итогового системного контекста;
- просмотр активных навыков, попадающих в prompt.

### Как пользоваться

1. Выберите AI-провайдера.
2. Заполните требуемые поля:
   - для `ProTalk`: `Bot ID`, `Bot Token`, `User Email`;
   - для `OpenAI` и `OpenRouter`: API Key.
3. Выберите модель.
4. Нажмите `Сохранить`.
5. При необходимости настройте параметры контекста:
   - количество последних команд;
   - глубину и объём списка файлов;
   - объём фрагментов файлов;
   - включение `stdout` и `stderr`.
6. Откройте блок `Системный контекст`, чтобы проверить итоговый prompt.

### Когда этот модуль особенно важен

- если агент отвечает слишком общо;
- если нужно уменьшить или увеличить объём контекста;
- если требуется сменить модель под цену, скорость или качество.

## 5. Модуль "Навыки"

### Что делает модуль

Навыки — это дополнительные системные инструкции, которые расширяют профиль AI-агента под конкретную задачу: разработка, маркетинг, аналитика, документы, базы данных, автоматизация, Telegram, email и другие сферы.

### Возможности

- просмотр каталога навыков;
- фильтрация по категории;
- поиск по названию;
- выбор активных навыков;
- создание собственного навыка;
- редактирование существующего навыка;
- хранение системного промпта навыка, примеров, тегов и метаданных.

### Как пользоваться

1. Откройте `Навыки`.
2. Найдите нужный навык через фильтры или поиск.
3. Отметьте нужные навыки.
4. Выбранные навыки начнут добавляться в AI-контекст.
5. Если готового навыка нет, нажмите `Добавить навык` и заполните форму.

### Практическая рекомендация

Не включайте слишком много навыков одновременно. Лучше активировать только те, которые действительно нужны для текущего сценария работы.

### Для чего использовать

## 7. Модуль "Файлы"

### Что делает модуль

Позволяет работать с файловой структурой пользователя и одновременно показывает информацию о персональной базе PostgreSQL.

### Основные зоны хранения

- `input` — входные файлы пользователя;
- `output` — результаты работы;
- `work` — рабочие файлы и промежуточные данные;
- `log` — журналы;
- `tmp` — временные файлы;
- дополнительные папки могут создаваться самим пользователем или агентом.

### Возможности

- drag-and-drop загрузка файлов;
- загрузка в `/workspace/input`;
- просмотр дерева каталогов;
- скачивание файлов;
- просмотр содержимого;
- удаление отдельных файлов;
- очистка каталогов;
- удаление нестандартных пользовательских папок;
- отображение дисковой статистики;
- показ реквизитов персональной PostgreSQL-базы.

### Как пользоваться

1. Откройте `Файлы`.
2. Перетащите файлы в зону загрузки или выберите их вручную.
3. Найдите нужный файл в дереве каталогов.
4. Используйте кнопки:
   - `⬇️` для скачивания;
   - `👁️` для просмотра;
   - `🗑️` для удаления.
5. Если нужно, очистите содержимое папки.

### Что показывает блок PostgreSQL

- имя базы;
- host и порт;
- имя пользователя;
- строку подключения;
- переменные окружения, через которые БД доступна внутри контейнера.

## 8. Модуль "Приложения"

### Что делает модуль

Показывает все процессы, запущенные через `pm2` внутри контейнера пользователя, и даёт базовое управление ими.

### Возможности

- просмотр списка процессов;
- отображение статуса, PID, CPU, памяти, времени работы;
- определение порта приложения;
- автообновление списка;
- перезапуск, остановка и другие действия над приложением;
- восстановление старых приложений через встроенный `fix`-механизм.

### Как пользоваться

1. Откройте `Приложения`.
2. Нажмите `Обновить`, чтобы получить актуальный список.
3. Включите автообновление, если отслеживаете запуск или падение процессов.
4. Используйте карточки приложений для контроля статуса.

### Когда это полезно

- если AI-агент создал приложение и его нужно проверить;
- если приложение не отвечает и требуется перезапуск;
- если нужно узнать, на каком порту поднят сервис.

## 10. Модуль "Контент-пайплайн"

### Что делает модуль

Это специализированный модуль генерации и публикации контента, ориентированный на Telegram-каналы и процесс модерации.

### Возможности

- ручной запуск генерации `Run now`;
- получение тем из Google Sheets;
- использование материалов из Google Drive;
- генерация текста и медиа;
- поддержка публикаций в формате `text+image` и `text+video`;
- очередь задач контента;
- модерация постов;
- публикация в канал;
- повторная генерация текста или изображения;
- метрики успешности за 24 часа и 7 дней;
- ограничение дневного лимита публикаций;
- выбор времени публикации и часового пояса;
- указание канала и модератора.

### Как пользоваться

1. Откройте `Контент`.
2. В блоке `Контент-настройки` заполните:
   - `Channel ID`;
   - `Moderator User ID`;
   - `Schedule Time`;
   - `Schedule TZ`;
   - `Daily Limit`.
3. Сохраните настройки.
4. Нажмите `Run now`, если хотите вручную запустить генерацию.
5. В таблице `Jobs` выберите нужную задачу.
6. В карточке задачи используйте действия:
   - `Approve`;
   - `Regen text`;
   - `Regen image`;
   - `Reject`.

### Что показывает модуль

- метрики публикаций;
- список job-задач;
- текст поста;
- статус публикации;
- логи публикации.

## 11. Модуль "Информация"

### Что делает модуль

Раздел предназначен для диагностики состояния пользовательской сессии.

### Возможности

- информация о контейнере и сессии;

## 13. Пользовательские хуки `/hook/:chatId`

### Что делает модуль

Маршрут `/hook/:chatId` перенаправляет запросы в обработчик внутри пользовательского контейнера.

### Поддерживаемые форматы

- `webhook_handler.js`;
- `webhook_handler.py`.

### Сценарий работы

1. Внешняя система отправляет запрос на `/hook/:chatId/...`.
2. Проект сохраняет данные запроса во временный файл внутри контейнера.
3. В контейнере запускается пользовательский обработчик.
4. Его stdout возвращается в HTTP-ответ.

### Где это полезно

- кастомные мини-API внутри контейнера;
- собственные webhook-интеграции;
- автоматизация без изменения основного backend-кода проекта.

## Где хранятся данные пользователя

- файловые данные: в пользовательском каталоге внутри `DATA_ROOT`;
