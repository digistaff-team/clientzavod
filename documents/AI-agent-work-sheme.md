### 📋 Детальное описание этапов работы

#### 1. Триггер по расписанию (Scheduler)
*   **Механизм:** Используется системный планировщик (например, `cron`, `Celery Beat`, `APScheduler` или GitHub Actions).
*   **Время:** Запускается строго в заданное время (например, каждый день в 09:00).
*   **Действие:** Инициализирует скрипт бота.

#### 2. Извлечение темы из БД (Data Fetching)
*   **Запрос:** Бот подключается к PostgreSQL и выполняет выборку первой доступной темы из таблицы контент-плана.
    *   *Пример SQL:* `SELECT id, topic FROM content_queue WHERE status = 'pending' ORDER BY created_at ASC LIMIT 1;`
*   **Блокировка:** Сразу после получения строки статус записи меняется на `'processing'`, чтобы избежать дублирования задач при параллельных запусках.
*   **Результат:** Агент получает строку с темой (например, *"Новые функции нашего приложения в марте"*).

#### 3. Генерация контента (AI Generation)
Этот этап состоит из двух параллельных или последовательных процессов:

*   **А. Генерация текста (LLM):**
    *   Агент отправляет тему в языковую модель с инструкцией: *"Напиши цепляющий заголовок и текст поста для Telegram на тему: {topic}. Тон: профессиональный, но дружелюбный."*
    *   **Результат:** Структурированный текст (Заголовок + Основной текст).

*   **Б. Генерация изображения (Image Gen):**
    *   Агент формирует промпт для генерации картинки на основе той же темы.
    *   Вызывается инструмент генерации изображений.
    *   **Результат:** Ссылка (URL) на сгенерированное изображение или бинарный файл.

#### 4. Согласование с пользователем (Human-in-the-Loop)
*   **Формирование сообщения:** Бот объединяет Заголовок, Текст и Картинку в одно сообщение.
*   **Интерактивные кнопки:** К сообщению прикрепляется клавиатура (Inline Keyboard) с кнопками:
    *   ✅ `Опубликовать`
    *   ❌ `Отклонить / Переписать`
    *   🔄 `Сгенерировать заново` (опционально)
*   **Отправка:** Сообщение отправляется в личный чат администратора/редактора, используя его `chat_id` (хранится в конфиге или БД).
*   **Ожидание:** Скрипт переходит в режим ожидания ответа (или использует webhook/callback_query handler).

#### 5. Финальная публикация (Execution)
Действия зависят от нажатой кнопки пользователем:

*   **Сценарий А: Пользователь нажал "Опубликовать"**
    1.  Бот берет токен канала (или использует права администратора уже авторизованного бота).
    2.  Отправляет сообщение (Текст + Картинка) в целевой канал через метод `sendPhoto` или `sendMediaGroup` API Telegram.
    3.  В базе данных (PostgreSQL) обновляет статус строки на `'published'` и записывает дату публикации и ссылку на пост.

*   **Сценарий Б: Пользователь нажал "Отклонить"**
    1.  В базе данных статус строки меняется на `'rejected'`.
    2.  Бот может удалить тему из очереди или переместить её в архив.
    3.  Пользователю приходит уведомление "Публикация отменена".

### 🛠 Техническая реализация ключевых моментов

#### 1. Работа с базой данных (PostgreSQL)
Таблица `content_queue` должна иметь примерно такую структуру:
```sql
CREATE TABLE content_queue (
    id SERIAL PRIMARY KEY,
    topic TEXT NOT NULL,
    status VARCHAR(20) DEFAULT 'pending', -- pending, processing, published, rejected
    generated_text TEXT,
    image_url TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    published_at TIMESTAMP
);
```

#### 2. Логика бота (Python + aiogram/telebot)
Псевдокод основного цикла:

```python
async def scheduled_task():
    # 1. Получить тему
    task = db.get_next_pending_task()
    if not task:
        return

    # 2. Сгенерировать контент
    text = llm.generate_post(task.topic)
    image_url = image_gen.create_image(task.topic)
    
    # 3. Сохранить черновик в БД
    db.update_task(task.id, text=text, image=image_url, status='waiting_approval')

    # 4. Отправить пользователю на согласование
    keyboard = InlineKeyboardMarkup().add(
        InlineKeyboardButton("✅ Опубликовать", callback_data=f"pub_{task.id}"),
        InlineKeyboardButton("❌ Отменить", callback_data=f"rej_{task.id}")
    )
    await bot.send_photo(
        chat_id=ADMIN_CHAT_ID,
        photo=image_url,
        caption=f"{text}\n\nПодтвердите публикацию:",
        reply_markup=keyboard
    )

# Обработчик нажатия кнопки
async def on_publish_callback(call: CallbackQuery):
    task_id = extract_id(call.data)
    task = db.get_task(task_id)
    
    # Отправка в канал
    await bot.send_photo(
        chat_id=TARGET_CHANNEL_ID, # ID канала из настроек
        photo=task.image_url,
        caption=task.generated_text
    )
    
    db.update_task_status(task_id, 'published')
    await call.message.edit_text("✅ Опубликовано в канале!")
```

#### 3. Безопасность и права доступа
*   **Chat ID:** `ADMIN_CHAT_ID` должен быть надежно сохранен в переменных окружения (`.env`), а не захардкожен.
*   **Права бота в канале:** Бот должен быть добавлен в канал как **Администратор** с правом "Публикация сообщений" (Post Messages). Другие права (удаление, изменение настроек) можно отключить для безопасности.
*   **Обработка ошибок:** Если генерация картинки не удалась, бот должен отправить только текст с пометкой "Картинка не сгенерирована" и предложить выбрать действие.

Эта схема обеспечивает полный цикл автоматизации: от выбора идеи до финальной публикации, оставляя человеку контроль над качеством контента перед выходом в эфир.
